## 1) نموذج المنتج التنفيذي — ثلاث بوابات فقط

البوابة الرئيسية تعرض **القسم أولًا**، لا الشركة.

### 1.1 برنامج المحاسبة الكامل
المسار التنفيذي:

`المحاسبة → القطاع/النشاط → النماذج والشركات داخل القطاع → فتح/إنشاء شركة → العمل المحاسبي`

داخل الشركة يجب أن تتكامل:
- التعريفات وشجرة الحسابات.
- القيود والترحيل والأستاذ.
- العملاء والموردون.
- المبيعات والمشتريات والتحصيل والمدفوعات.
- المخزون والمستودعات.
- مراكز التكلفة والمحركات القطاعية.
- الضرائب والامتثال.
- التسويات والإقفال.
- القوائم المالية.
- التقارير والطباعة.
- التحليل المالي والإحصائي.
- التنبؤ والسيناريوهات.
- مهام المحاسبين والمتابعة.
- الأدوات المساعدة التي يختار المستخدم تركيبها.

يوجد ربط اختياري واضح مثل **«راجع هذه الشركة»** لإرسال السياق المطلوب إلى قسم المراجعة فقط عند طلب المستخدم.

### 1.2 المراجعة والتدقيق
قسم مستقل؛ لا يشترط وجود شركة في المحاسبة.

المسار:
`المراجعة → ملف/شركة مراجعة → تحديد النطاق → البيانات والمستندات → جولات المراجعة → مجلس AI/Jev → التقرير النهائي`

يجب دعم:
- مراجعة قوائم كاملة.
- مراجعة بند/مستند/مجموعة مستندات.
- أسئلة المعايير والمعالجة.
- PBC وطلبات الأدلة.
- تقييم المخاطر والأهمية النسبية.
- إجراءات تحليلية واختبارات تفصيلية.
- جولات متعددة حتى كفاية الأدلة أو إثبات عدم توفرها.
- مجلس مراجعين متعدد الآراء.
- Jev كحكم عند الاختلاف.
- أثر نقص الأدلة وعدم اليقين على النتيجة.

### 1.3 الأدوات المساعدة
مدخل مستقل، ويمكن للأداة أن تعمل:
- بلا شركة.
- داخل مساحة أدوات.
- أو تُركب اختياريًا داخل شركة محاسبية بعقد ربط واضح.

العائلات الأساسية:
- البيانات والملفات.
- المطابقات والتسويات.
- التكاليف والتسعير.
- التحليل والتنبؤ.
- الرقابة والجودة.
- الضرائب والامتثال.
- الإنتاجية والأتمتة.
- المطور والتكامل.

**التقارير، AI، المكتبة، التحليل، المستندات، الصلاحيات، والأرشيف طبقات مشتركة وليست بوابات رابعة.**

## 2) التخصص القطاعي — Core مشترك + Sector Packs

النواة المحاسبية مشتركة، لكن القدرات تعاد بلورتها حسب القطاع؛ لا يكفي تغيير أسماء الحسابات.

### القطاعات ذات الأولوية القصوى
1. المستشفيات والرعاية الصحية.
2. الفنادق والضيافة.
3. المقاولات والمشروعات.
4. اللحوم والتصنيع/التجزئة المرتبط بها.
5. التسويق الإلكتروني.

وتظل قطاعات التعليم، المصانع، المخابز، الزراعة، والتجارة العامة مدعومة.

### أمثلة عمق إلزامي
- **المستشفيات:** تأمين ومطالبات ورفض وتسويات، تكلفة الحالة والخدمة، الصيدلية، المختبر، الأشعة، الأطباء والعمولات، مراكز التكلفة، الذمم، التكاليف المعيارية والفعلية.
- **الفنادق:** الغرف والحجوزات والإشغال، F&B، الودائع، القنوات والعمولات، الإقفال الليلي، Housekeeping والصيانة، ربحية الغرفة والقسم.
- **المقاولات:** العقود، BOQ، المستخلصات، نسب الإنجاز، WIP، المحتجزات، التغيير، مقاولو الباطن، التكلفة والربحية المتوقعة.
- **اللحوم:** الأوزان وYield والتقطيع والتحويل والهدر والمنتجات الثانوية والتعبئة والتتبع البارد وتكلفة الكيلو/القطعة.
- **التسويق الإلكتروني:** العملاء والحملات والقنوات، الإنفاق الإعلاني، Retainer/Project، العمولات، الربحية حسب العميل/الحملة/القناة.

## 4) المكتبة المالية المرجعية الرسمية واختبار المراجعة

المرجع الرسمي:
**KOSIF · مكتبة المرجع المالي**  
https://kosif-financial-reference-library.smartsphere152.chatgpt.site/

الموقع يعرض مرجعًا من **12,506 صفحة** ويستخدم كنقطة الدخول الرسمية للتقارير المرجعية والـPDF/الصفحات الأصلية المرتبطة به.

### المطلوب
- كل شركة/حالة قابلة للاستخراج من المرجع تتحول إلى Benchmark Case في المراجعة.
- يرتبط كل Case بمصدره وصفحاته الأصلية.
- يعاد تشغيل دورة المراجعة End-to-End باستخدام الـAI المحلي/AI Brain Connector عند تفعيله.
- يقارن التقرير الناتج بالتقرير المرجعي في:
  - نوع الرأي والاستنتاج.
  - المخاطر/الأمور الجوهرية.
  - الأهمية النسبية حيث يمكن المقارنة.
  - النسب والأرقام.
  - العرض والإفصاح.
  - بنية التقرير.
  - الصياغة المهنية.
  - جودة التصميم والطباعة.

**لا يشترط التطابق الحرفي، لكن يجب استهداف تقارب مهني ومضموني وبصري مرتفع جدًا مع تفسير الفروق.**

### Synthetic Reverse Engineering
يجوز إعادة بناء Audit Test Pack اصطناعي انطلاقًا من التقرير المنشور:
- استنتاج أنواع المستندات المحتملة.
- إنشاء ميزان، أستاذ، كشوف، عقود، فواتير، مصادقات، أصول، مخزون، ضرائب، رواتب وغيرها حسب الحالة.
- محاكاة شكل المستند المتوقع لاختبار الاستخراج والمراجعة.

لكن يجب فصل بوضوح بين:
1. **مستخرج فعليًا من المرجع**.
2. **مستنتج منطقيًا**.
3. **Synthetic Reconstruction** مولد للاختبار.

لا يجوز نسبة مستند اصطناعي إلى الشركة باعتباره مستندًا تاريخيًا حقيقيًا.

### مخرجات Benchmark
لكل حالة:
- Evidence Trace.
- Benchmark Comparison.
- Scorecard.
- Regression Result.
- Failure Log.

## 5) اعتماد الـAI المحلي وAI Brain Connector

### 5.1 Local/External AI Provider Bridge
يمكن ربط AI محلي أو خارجي ليعمل كعقل عام للتطبيق مع بقاء الوظائف الحتمية عاملة بدونه.

يستخدم في:
- التفسير.
- مجلس المراجعة.
- تحليل المستندات.
- اقتراح المطابقات.
- التحليل والتنبؤ.
- توليد القوالب.
- المساعدة في التطوير والـPatches.

### 5.2 AI Brain Connector
يوفر التطبيق App Context Package حديثًا يصف:
- الأقسام والصفحات.
- Schemas والعلاقات.
- الأدوات والقدرات.
- الصلاحيات.
- نطاق البيانات المسموح.

كل Context يحمل Version ووقت إنشاء وصلاحية. السياق الحساس يمكن أن تكون صلاحيته القصيرة الافتراضية نحو 15 دقيقة، مع قابلية الضبط. عند تغير Schema/القدرات أو انتهاء الصلاحية يجب طلب Context حديث.

### 5.3 Open Session Bridge / No-API Mode
يجوز توصيل جلسة Claude/ChatGPT/مزود آخر مفتوحة بالفعل عند المستخدم عبر Local Bridge أو Browser/Desktop Adapter.

شروط إلزامية:
- لا استخراج كلمات مرور.
- لا نسخ Cookies أو Session Tokens.
- لا تجاوز المصادقة.
- الجلسة ملك المستخدم ويمكن فصلها فورًا.
- أي Action يظل خاضعًا لـPermissions/Policy/Schema Validation/Audit Trail.
- Browser Adapter معزول عن قلب النظام لأن واجهات المواقع قابلة للتغير.

### 5.4 مختبر اعتماد AI
النماذج المحاسبية وحالات المراجعة المرجعية تشكل Golden Benchmark مستمرًا.
أي تحديث للـAI أو التطبيق يجب ألا يخفض النتائج التي كانت ناجحة دون تفسير واعتماد صريح.

## 7) Professional Report Rendering & Print Engine

التقارير ليست Dashboard مطبوعًا.

### فصل الطبقات
- **Data/Calculation Layer:** SQL/Queries/Views/محركات الحساب.
- **Presentation Layer:** HTML/CSS/Print CSS/Templates.
- **Generation Layer:** Python/JavaScript/Document Rendering عند الحاجة.

### معايير إلزامية
- A4/A3، Portrait/Landscape.
- رؤوس وتذييلات وترقيم صفحات.
- Repeatable table headers.
- Page-break control.
- RTL عربي وLTR إنجليزي.
- تقارير ثنائية اللغة عند الحاجة.
- Typographic hierarchy احترافي.
- تنسيق عملات ونسب وسوالب وإجماليات.

- Charts مناسبة للطباعة.
- PDF مطابق للمعاينة.

يجب دعم تقارير طويلة **100–150+ صفحة** عند ما تستدعيه الحالة، مع TOC وأقسام وملاحق وإيضاحات، بدون حشو مصطنع.

أي تقرير مرجعي يعتمد عليه المالك يحلل إلى:
- Grid.

- Tables.
- Notes.

## 12) خطة التنفيذ الحديثة — لا تعتمد على Snapshot قديم

أي جدول قديم للحالة أو خطة M1–M7 يعتبر **تاريخًا تنفيذيًا فقط**، وليس وصفًا حاليًا مضمونًا.

قبل بدء التنفيذ:
1. نفذ Rule Zero inventory.
2. افحص `main` الحالي.
3. افحص PRs/Branches/Issues ذات الصلة.
4. حدّث Capability Registry.
5. أنشئ Current-State Report بتاريخ التنفيذ.
6. حدد Gap مقابل `FOUNDATION.md`.
7. ابنِ خطة موجات قابلة للاختبار.

### الموجات الموصى بها

#### P0 — Discovery & Inventory
- كل المستودعات.
- كل القدرات والطلبات والتجارب.
- Registry موحد.
- إزالة التكرار.

**قبول:** لا توجد قدرة معروفة بلا تصنيف أو قرار.

#### P1 — Navigation & Information Architecture
- ثلاث بوابات.
- Accounting: Sector → Company.
- Audit مستقل.
- Tools مستقل.
- Responsive mobile/desktop.

**قبول:** E2E navigation يثبت الفصل وعدم خلط البوابات.

#### P2 — Accounting Core Integrity
- Ledger as source of accounting truth.
- Postings مترابطة.
- Reconciliations.
- Close.
- Traceability.

**قبول:** عملية → قيد → أستاذ → ميزان → قوائم بالأرقام نفسها.

#### P3 — Sector Packs
- Hospital/Hotel/Construction/Meat/Digital Marketing أولًا.
- ثم القطاعات الأخرى.

**قبول:** نفس القدرة تتصرف حسب Sector Pack وليس مجرد تغيير مسميات.

#### P4 — Audit Platform
- Intake.
- PBC.
- Risk/materiality.
- Fieldwork.
- Council/Jev.
- Reporting.

**قبول:** حالة كاملة من مستندات إلى تقرير.

#### P5 — Reference Corpus Benchmark
- إدخال كل الحالات من مكتبة 12,506 صفحة.
- Synthetic test packs.
- Local AI runs.
- Scorecards/Regression.

**قبول:** Benchmark matrix لكل حالة قابلة للتشغيل.

#### P6 — Helper Tools
- إعادة توزيع الموجود.
- ابتكار أدوات من الجرد والمرجع.
- Contracts + Integration Health.

**قبول:** كل أداة لها Owner/Inputs/Outputs/Tests/Placement.

#### P7 — AI Brain Connector
- Provider bridge.
- Context package.
- Open Session Bridge.
- Permissions/Audit.

**قبول:** AI يستطيع تنفيذ مهمة حقيقية عبر أدوات محكومة دون وصول خام غير مقيد.

#### P8 — Reporting & Print
- Report engine.
- Financial/audit templates.
- Long-report support.
- Visual regression.

**قبول:** PDF احترافي قابل للطباعة ويصل لمستوى المراجع المعتمدة أو أعلى.

#### P9 — Developer Extensions
- Export context.
- Patch pipeline.
- Sandbox.
- Rollback.

**قبول:** تعديل نموذج/صفحة تجريبيًا من Patch مع Preview واختبارات وRollback.

#### P10 — Hardening
- Security.
- Permissions.
- Data isolation.
- Performance.
- Backups.
- Observability.
- Regression suite.

**قبول:** لا يوجد Critical regression في المحاسبة أو المراجعة أو البيانات.

## 13) قواعد العمل لكل Agent

- اقرأ `FOUNDATION.md` كاملًا أولًا.
- لا تعتمد على Status قديم؛ تحقق من الكود الحالي.
- لا تحذف قدرة قبل جردها وتقييمها.
- لا تنسخ UI قديم فقط لأنه موجود.
- لا تنشئ بوابة رئيسية رابعة من طبقة مشتركة.
- لا تخلط بيانات الشركات.
- لا تعتمد على AI لحساب يجب أن يكون حتميًا وقابلًا للتحقق.
- لا تنسب Synthetic data إلى شركة حقيقية.
- أي تغيير معماري يجب أن يثبت عدم كسر المحاسبة والمراجعة.
- أي تضارب مع الدستور يحسم لصالح الدستور.
- إذا غيّر المالك معنى المنتج صراحةً: حدّث `FOUNDATION.md` أولًا ثم هذا الملف.

## 14) Definition of Done

لا تعتبر أي مرحلة مكتملة إلا إذا:
- حافظت على معنى المنتج.
- حافظت على فصل البوابات.
- البيانات قابلة للتتبع.
- الحسابات الحتمية مختبرة.
- الواجهات تعمل Mobile/Desktop.
- العلاقات والتكاملات لها Health checks.
- AI actions قابلة للتدقيق.
- التقارير قابلة للطباعة باحتراف.
- Regression suite خضراء.
- الوثائق وRegistry محدثة.
- تم تسجيل أي قدرة مستبعدة وسببها.
