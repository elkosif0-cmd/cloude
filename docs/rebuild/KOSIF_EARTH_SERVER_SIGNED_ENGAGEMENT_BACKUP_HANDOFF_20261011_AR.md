# KOSIF EARTH — تسليم النسخة الموقعة من ملف المراجعة بين المستودعين

**التاريخ:** 11 أكتوبر 2026 · **الفرع الأصلي لـEARTH:** `chatgpt/kosif-earth-manual-merge-20261010` من Commit `e482543` · **الفرع الخلفي:** `kosif199022-jpg/kosif-audit-studio`، Draft PR #42، Commit **`5437f363f17e509a55837530039b6ec6544f044a`**.

## التنفيذ المؤكد في الخادم وليس في واجهة المستخدم
أُضيفت إلى كود الخادم في PR #42 وحدة `cloudflare/engagement-backup.js` وربطها بـ`engagement-api.js` عبر مسارين:
- **`GET /api/engagements/:id/backup`**: إنشاء ملف **موقع HMAC من الخادم** لحالة ملف المراجعة المحفوظة في D1 فقط. يتضمن معرف الشركة ومساحة العمل وصاحب الملف، رقم إصدار الحالة، SHA-256، تاريخ الإصدار وانتهاء الصلاحية، وقائمة صريحة للمحتوى المستبعد.
- **`POST /api/engagements/:id/backup/preview`**: التحقق من التوقيع وبصمة الحالة وصاحب الشركة/المساحة والملف وصلاحية الحزمة وانتهاء صلاحيتها واختلاف الإصدارات، وإرجاع **خطة فحص بلا كتابة**. دائمًا `restoreAllowed:false` و`writePerformed:false`.

يتطلب كلا المسارين نمط `KOSIF_TENANCY_MODE=strict`، توكن ملف المراجعة، JWT هوية موثقة بالـissuer/audience وبصمة D1 `engagement_ownership`، إضافة إلى مُعرِّف مسؤول في إعدادات الخادم `KOSIF_BACKUP_ADMIN_SUBJECT` وسر توقيع خاص `KOSIF_BACKUP_HMAC_SECRET` منفصل عن JWT. غياب أي شرط يغلق المسار تلقائيًا؛ لا يسمح باختيار المسؤول من الواجهة. النسخة الموقعة صالحة لمدة 24 ساعة. **هذه صلاحية تشغيلية أولية لشخص واحد مضبوطة في الخادم، وليست بعد نظام RBAC أو موافقات مستقلة.**

تعاملت مراجعة السجلات مع `companyId` و`workspaceId` داخل بنية ملف المراجعة ولو في حقول متداخلة؛ رفضت أي وسم شركة أخرى. يظل المصدر القديم غير الموسوم بالمالك **غير مثبت التبعية**. لم يتم نسخ مرفقات R2 ولا قيد واحد من دفتر محاسبة قديم.

## اختبار التنفيذ والحدود
- داخل مستودع الخادم: **17/17 اختبارًا خاصًا بالملكية والتوقيع**، منها شركتان A/B، وهوية غير صحيحة، مفتاح توقيع غير مهيأ أو مطابق لمفتاح JWT، العبث بالمحتوى، انتهاء الحزمة، وجود شركة أخرى في الأدلة المتداخلة، واكتشاف تعارض الإصدار بدون كتابة.
- خادم V5 بالكامل: `npm test` **229/229 PASS**، وفحص `npm run check` PASS (18 واجهة قديمة + 35 معرف V5 + 86 استيرادًا/أصلًا + 137 وحدة JavaScript + 23 ملف CSS).
- **هذه نتائج محلية فقط:** لم تُضبط أسرار إنتاجية، ولم يُنشر الخادم على Cloudflare Staging أو الإنتاج، ولم نختبر D1/R2 حقيقيين أو اعتمادات بشرية.
- لا يوجد مسار `restore/commit` فعلي، ولا أخذ نسخة كاملة قابلة للاستعادة لشركة بما فيها القيود والمخزون والمشتريات والملفات.

## ما يبقى معلقًا في واجهة EARTH
- احتفاظ شاشة `devices.js` بحظر نقل الجهاز الشامل لأن حزمته السابقة تشمل بيانات شركات متعددة.
- بقاء `workspace.js` على تصدير محلي محدود `customers` و`sales_lines` و`orders` حسب `companyId`، وموسوم بأنه **غير صالح للاستعادة الكاملة**.
- عدم ربط زر RESTORE أو EXPORT الموقّع بواجهة المستخدم قبل وجود خادم فعلي وبنية أدوار مسؤول/مُراجع، وتحقق الحماية من ملفات مرفقة ودليل ملكية المصدر.
- عدم دمج PR #42 أو #247 أو تشغيل الإنتاج بناء على الفحص المحلي فقط.

## تسلسل الاستكمال
1. تحديد مصدر هوية JWT وRBAC موثوقين للمسؤول والمُراجع المستقل، وربط أذونات الملف بالشركة ومساحة العمل ودور المستخدم.
2. Staging محمي: D1 migration ثم R2 مع manifest نسخة شركة كاملة وتحميل مرفقاتها بحدود ملكية المصدر، مع مفاتيح خادم وسجلات تاريخية دون تسريب.
3. اختبارات شركتين A/B، الأرصدة والقيود والمخزون وطلبات الموردين والأدلة، ومحاولة استعادة عابرة للشركات، وانقطاع الاستعادة ثم rollback بلا فقد بيانات.
4. تصميم `prepare → preview → human approve → commit → rollback` وتحديد صلاحيات كل خطوة من الخادم، ثم ربط الواجهة وتكرار اختبارات Edge/CI.
5. فتح النقل/الاستعادة فقط بعد توثيق محضر نجاح اختبارات Staging والمراجعة البشرية.
