## الميزات التي نُقلت من الفرع الأحدث

- بحث وتصفية داخل قائمة الشاشات يُعلن عدد النتائج وينتقل باستخدام Enter إلى الشاشة أو التبويب الفعلي، لا مجرد عنوان قسم.
- قائمة جانبية هادئة ومتجاوبة تفتح مجموعة الشاشة الحالية؛ بحث عربي ومسارات وصول لكل من الأقسام الثلاثة.
- خريطة هدف → خطوات → نتيجة مع وجهات حقيقية داخل القدرات المثبتة، ومساعدة سياقية للشاشات.
- إضافة أدوات الشركة اختياريًا دون تغيير أدوات شركة أخرى؛ التخزين الجديد مفتاحه `companyId` المرمّز بدقة، وترحيل قديم فقط إذا تطابق المالك صراحةً، دون حذف سجل المصدر.
- تنظيم دخول مراجعة الحسابات داخليًا بلا استيراد تلقائي إلى ملف مراجعة مستقل، وإعادة رسم تبويب دفتر الحسابات داخل مالك الشاشة الصحيح.
- عناصر العلامة البصرية وهوية KOSIF EARTH الدافئة والواجهات الجديدة، مع الإبقاء على باب الدخول المضيء الأحدث الموجود في `main`.

كشف PR #251 بعد الرفع الأول ثلاث نقاط دقيقة:

## مرحلة تصحيح بوابات CI النهائية
- `tools/identity_check.py` كان يرفض وصف صفحة الدخول الذي لا يتضمن كلمة «المراجعة» نصًا، وقد أصبح الوصف واضحًا: KOSIF EARTH — المراجعة الذكية والمحاسبة وأدوات الشركات. بعد إعادة المعاينة نجحت **جميع قواعد الهوية** والدستور **18/18**.
- فشل `presentation` كان مثبتًا في **نسخة الأساس** نفسها وليس ملفاتنا: من أدلة GitHub Actions الفعلية `baseline-empty-report-context.json` عند `SQC_TESTED_SHA=0b6c97e` كانت `previewCount=0` في دفتر حسابات فارغ، بينما الاختبار ينتظر وجود `.rp-cover` مطبوع. عُدّل **اختبار التوقع فقط** ليطالب بالرفض نفسه للنسختين (baseline وcandidate) عند عدم وجود قيود، مع إبقاء باقي اختبارات التقرير والجداول وPDF والهوية دون تعديل. لا يجوز اختراع تقرير صفري لاجتياز CI.
- نشر GitHub Pages عبر `.github/workflows/pages-deploy.yml` يتطلب سر المستودع `CLOUDFLARE_API_TOKEN`؛ فحص أسماء أسرار المستودع كشف وجود `KOSIF_UNLOCK_PASSWORD` و`WA_DISPATCH_TOKEN` فقط. لا يساوي نجاح بناء Artifact أو Job اسمه deploy تحديث صفحات Cloudflare فعليًا. يجب تهيئة سر Pages Edit من حساب المستخدم المصرح له، ثم التأكد من حدوث Production deployment جديد على `s-kosif.pages.dev`.
