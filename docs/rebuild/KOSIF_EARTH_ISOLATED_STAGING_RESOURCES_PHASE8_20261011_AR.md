## لماذا لم ننشر Worker Staging؟

**ما زال مصدر الهوية الموثوق غير مُعرّف.** فحص التهيئة أعاد `kosif_auth_issuer_unconfigured`، وكود خروج 2، و`liveDeploymentAuthorized:false` كما ينبغي. تركنا `KOSIF_AUTH_ISSUER` غير محدد ولم نخترع جهة إصدار أو نكتب مفاتيح JWT/HMAC داخل Git أو سجل المحادثة.

إعداد `KOSIF_AUTH_AUDIENCE=kosif-audit-staging` لا يغني عن issuer فعلي؛ كما يجب تركيب أسرار الخادم وربط مدير حقيقي بالموافقة، واختبار هوية شركتين وملفين ومرفقات R2 عبر HTTP ثم اختبار الاستعادة الآمنة.

**المخاطر المفتوحة:** ليست هناك نسخة احتياطية قابلة للاستعادة لكل شركة بعد؛ ملف EARTH المحلي محدود وموسوم `restorable:false`، ونقل الجهاز الشامل موقوف. تُعد أي محاولة لاستعادة أو توزيع بيانات شركتين دون هوية خادم موثوقة مخالفة لمتطلبات الإصدار.

## المسار القادم عند جاهزية الهوية

ربط مصدر JWT موثوق بمطالبات `sub/companyId/workspaceId/iss/aud/iat/exp`، وتركيب أسرار خادم فقط في Worker الاختبار المستقل، ثم تفعيل مسار HTTP Staging اختبارًا وإثبات الرفض لشركة B أمام ملف شركة A على endpoints الحالة والمستندات والنسخ الموقعة. بعد ذلك تصبح مرحلة تصميم `prepare/approve/commit/rollback` (مراجعتان بشريتان) قابلة للنقاش؛ لا تفعيل استعادة إنتاجية الآن.
