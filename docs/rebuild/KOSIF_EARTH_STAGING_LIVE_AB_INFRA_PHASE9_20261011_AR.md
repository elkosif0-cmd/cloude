**التاريخ:** 11 أكتوبر 2026. **EARTH:** PR #247، فرع `chatgpt/kosif-earth-manual-merge-20261010`. **خادم المراجعة:** PR #42، Commit `0b6a7895ff005ad7a2e3883e875312a25f4845c7`، وكلاهما Draft.

## ما تم اختباره فعليًا في Cloudflare Staging المعزولة

- D1: قاعدة `kosif-audit-tenant-staging-20261011`، UUID `2bf580c6-6a80-41bb-a59c-f96a6b4d3c0f`، وتوجد فيها الجداول والفهارس اللازمة لهجرات `0001` و`0002` و`0003`.
- R2: حاوية مستقلة `kosif-audit-tenant-staging-docs-20261011`.
- **شركتان وهميتان A وB على D1 الفعلية:** إنشاء ملفي مراجعة وسجلي ملكية؛ الاستعلام بشرط `company_id + workspace_id + owner_subject` أعاد ملف الشركة المقصودة فقط؛ مزج شركة A مع مستخدم B أو مساحة B أعاد صفر نتائج.
- **ملفات R2 اصطناعية:** نجح رفع ملف لكل من `staging-proof/A/` و`staging-proof/B/`، واستعلام كل prefix أعاد ملفه وحده. حُذف الملفان بعد الاختبار.
- **حراسة مفتاح مستند D1 عالمي:** وُضع مستند اصطناعي B بمفتاح `DOC-STG-CONFLICT-20261011`. محاولة A تنفيذ UPSERT على نفس المفتاح أعادت `changes=0` وحافظت على سجل B واسمه؛ تحديث B لنفسها أعاد `changes=1`.
- **تأكيد التنظيف النهائي من API:** `engagements=0` و`engagement_ownership=0` و`documents=0` و`engagement_sessions=0`، ولا توجد ملفات داخل `staging-proof/` على R2.
- **حد الإثبات:** كل اختبارات الموارد تمت باستخدام API إداري موثوق على موارد منفصلة، *وليس* بطلبات مستخدمين HTTP إلى Worker منشور؛ لذلك هي بروفة للموارد ولشروط SQL والمسارات فقط، وليست شهادة عزل JWT/RBAC عبر Worker.

## خلل إنتاجي متوقع أُغلق في مسودة خادم PR #42

كان كود رفع المستند يسمح بـ`documentId` يحدده العميل، ويحفظ البيانات عبر `INSERT OR REPLACE INTO documents` رغم أن `documents.id` مفتاح عام للملفات. قد يعيد ذلك نسبة مستند من ملف مراجعة آخر.

- أصبح `gateway-worker.js` يرفض منذ البداية إعادة استخدام معرف مستند موجود بالفعل لملف مراجعة أجنبي بـ`409 document_id_not_available`، قبل الرفع إلى R2 أو التحليل.
- يستخدم `document-worker.js` عملية `INSERT... ON CONFLICT(id) DO UPDATE ... WHERE documents.engagement_id=excluded.engagement_id`؛ شرط D1 يمنع السباق بين فحص الـGateway والكتابة.
- إذا فشلت الكتابة في D1، لم تعد واجهة رفع المستند تعيد `ok:true` أو تستكمل التحليل: تعيد 409 للتعارض أو 503 عند تعذر التخزين.
- خمسة اختبارات جديدة تحقق من محاولة A تغيير مستند B، وتحديث المالك الصحيح، وسباق المعاملة (`changes=0`)، وتعطل D1، ورفض Bearer الخاطئ.
- اختبارات الخادم `npm test` **246/246 ناجحة**، و`npm run check` ناجح، وفحوص المستندات المركزة 15/15.
- المرجع التفصيلي في الخادم: `docs/KOSIF_EARTH_STAGING_AB_D1_R2_DOCUMENT_ID_PHASE9_20261011_AR.md`.

## بوابات لا تزال تمنع الإنتاج

1. لا مُصدر JWT مُتحقق منه على Staging: `KOSIF_AUTH_ISSUER` مفقود صراحة من إعداد الاختبار. فاحص الجاهزية أعاد `readyForOfflineReview:false` و`liveDeploymentAuthorized:false`، ولم تُستخدم أسرار أو مفاتيح في المحادثة.
2. لم ننشر Worker على Staging ولم نختبر HTTP عبر هوية شركتين؛ لا يوجد إثبات live لملكـية مستندات R2 أو تطبيق RBAC على الاستدعاءات.
3. قد تبقى ملفات R2 يتيمة عند نجاح الرفع وفشل كتابة D1: مطلوب تصميم حجز/تسوية وتحكم تنظيف آمن قبل الإنتاج.
4. النسخة الكاملة القابلة للاستعادة لكل شركة لم تُنفذ، ولا تزال وظائف `EARTH` الحالية `restorable:false`، ونقل الجهاز الشامل معلقًا.
5. لا اعتماد بشري ثنائي ولا هجرة ملكية دفتر الأستاذ والمشتريات والمخزون ومرفقاتهم.

**التالي:** إنشاء أو ربط مصدر هوية JWT موثوق بواسطة صاحب الصلاحية، وضبط أسرار الخادم *خارج Git*، واختبار Worker بعميلَي A/B والملفات R2 مع حالات الرفض والتوقيع وحفظ الأثر، مع بقاء الفرعين كمسودتين دون دمج main أو إنتاج.
