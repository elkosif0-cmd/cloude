# KOSIF EARTH — المرحلة السادسة: معاينة استعادة شركة واحدة دون كتابة بيانات

**التاريخ:** 11 أكتوبر 2026. **فرع التطوير:** `chatgpt/kosif-earth-manual-merge-20261010`، الأساس Commit `e482543`. **القرار:** لا دمج في main ولا نشر للإنتاج دون اختبار خادم حقيقي وهوية موثوقة.

## ما نُفّذ فعليًا

أُضيفت الدالة `SK.legacyCompanyData.previewRestore(fileText)` إلى `ui/core/legacy-company-data.js`، وواجهة اختيار ملف JSON وزر «فحص الملف والفروق فقط» في `ui/features/workspace.js` داخل شاشة التصدير.

**المعاينة قراءة فقط تمامًا.** لا تستدعي `SK.store.restore` أو `writeIdb`، ولا تستبدل قيدًا أو فاتورة أو عميلًا، ولا تهيئ واجهة «تأكيد الاستعادة».

تأخذ صيغة `kosif-company-scoped-local-export` السابقة (الإصدار 1، الموسومة `restorable:false`) وتطبق الشروط:

- ملف JSON محدود بـ **3 MiB تقريبًا** على مستوى النص ومدخلات المتصفح.
- تحقق من النوع والإصدار، وقيمة `restorable:false`، ووسم الصلاحية المحلية غير الموثقة، وعدم وجود حقول خارج قائمة manifest المسموح بها.
- تحقق من معرّف **الشركة الحالية** وإلغاء العملية عند تبديل A→B→A أو بدء تحميل الشركة أثناء القراءة.
- تحقق من مخازن `customers` و`sales_lines` و`orders` فقط، مع عدد السجلات الصريح في كل مصدر، وحد 25 ألف سجل.
- رفض أي سجل يحمل معرّف شركة آخر، أو بنية داخلية تحاول حمل معرّف أجنبي، أو مفاتيح `__proto__ / constructor / prototype`، أو معرف سجل مفقود أو مكرر. يمنع وجود مبيعات تشير إلى طلب غير موجود في الملف.
- مقارنة أعداد المعرّفات الموجودة في الملف والأصل المحلي: الجديدة، والمشتركة، والموجودة محليًا وغير الموجودة في الملف. **المعرّف المشترك لا يعني تطابق محتوى السجل**.
- نتيجة التقرير لا تحتوي على اسم العميل أو محتوى سجل أو ملف أو توكن؛ `restoreAllowed:false` و`writesPerformed:0` دائمًا.

## حدود مهمة

هذه **معاينة محلية غير موقعة**، وليست نسخة احتياطية يمكن استعادتها، وليست إثباتًا لمصدر البيانات أو تفويض المستخدم؛ ما زالت `restorable:false`، ولا يجوز «إصلاحها» بقلب القيمة إلى `true`. وهي لا تشمل القيود العامة والمخزون والمشتريات والمرفقات أو كافة بيانات الشركات.

المنهج الصحيح للاستعادة الفعلية لاحقًا يتطلب: خريطة ملكية موثقة لكل مصدر، مُصدر هوية JWT مع أدوار واضحة، خادم توقيع وإصدار manifest لكل شركة/مساحة عمل، نسخ مرفقات R2 محكومة بالصلاحية، معاملات D1 وخطة snapshot + rollback، اختبارات عزل A/B ومنع حقن السجلات وتحقق مصادقة مستقل.

## الاختبارات

- إضافة خمسة سيناريوهات في `tools/legacy_company_data_adapter.test.mjs` لمعالجة مقارنة المعرّفات دون كتابة، ورفض التلاعب والنطاقات الخاطئة، والتكرار والمفاتيح السامة، والطلب المفقود، وتبديل الشركة أثناء القراءة. **16/16** فحوص هذه المجموعة نجحت؛ وبعد تشديد رمز دورة الشركة، اختبارات المصدر وبوابة النقل المتخصصة **19/19** ناجحة.
- بناء المعاينة **194 مدخلًا** ولا توجد `dist/secure`، ودستور التطبيق **18/18**.
- المجموعة الشاملة للأدوات **1290/1290 PASS** (بدأت قبل التحسين الإضافي الأخير الذي يرفض غياب رمز دورة انتقال الشركة؛ أعقبه فحص مركز **19/19 PASS** للكود بعد التحسين). Microsoft Edge على الكمبيوتر والجوال **26/26 فحصًا اصطناعيًا ناجحًا**: تنزيل ملف الشركة ورفعه للمعاينة، ثم رفض نسخة تغير معرّف شركتها، دون أخطاء JavaScript أو استعادة فعلية. الاختبارات ليست على خادم Cloudflare المنشور.

**الخطوة التالية:** تجهيز تنسيق manifest موقّع على الخادم مع أذونات صلاحية الاستعادة وملفات فحص مصدر D1/R2، ثم اختبارات مرور بيانات شركة A وعدم ظهور أي سجلاتها عند شركة B على بيئة Staging قبل تفعيل زر استعادة إنتاجي.
