# KOSIF EARTH LUXE — المرحلة التنفيذية الأولى (17 أكتوبر 2026)

## الطلب والسياق
المالك طلب تطوير التطبيق الرسمي `https://earth.kosif.pp.ua/` إلى منصة محاسبة ومراجعة فاخرة بنظام واجهات عالمي، مع أولوية لإظهار الشركة أعلى الصفحة وتقليل ازدحام أيقونات الهاتف. **هذه ليست إعادة إنشاء مشروع**؛ التغيير على المستودع الرسمي `elkosif0-cmd/cloude` فقط، من دون تعديل بيانات المستخدمين أو دفتر الأستاذ أو المصادقة.

## مراجعة الموجود قبل التعديل
- `ui/layouts/topbar.js` يعرض بالفعل الشركة والفترة في الشريط العالمي؛ لذلك **لم يُنشأ رأس جديد أو مبدّل شركة مكرر**.
- `ui/ds/luxe.css` يخفي على الهاتف نص الفترة ويترك أيقونتها فقط، ويعرض إشعارات/مظهر/بحث/حساب المستخدم في الصف الضيق نفسه.
- `ui/core/company.js` يزوّد سياق الشركة والفترة في بوابة المحاسبة؛ بوابتا المراجعة والأدوات تبقيان مستقلتين.
- موجود بالفعل `KOSIF Luxe` وIBM Plex Sans Arabic ومظهر ليلي ومساعدات تنقل واختبارات للواجهة؛ **يجب تطويرها لا نسخها**.
- مسودات UX #241 و#242 و#245 تحتوي أفكارًا مفيدة ولكن متراكبة؛ هذه المرحلة لا تدمجها ولا تغيّر معماريتها.

## التعديلات الفعلية في هذا الفرع
1. اسم الشركة أو ملف المراجعة أو مساحة الأدوات يبقى في الشريط العلوي مع `aria-label` و`title` كاملَين حتى لو اقتُطع نصه على الهاتف.
2. تسمية الفترة المالية أو فترة المراجعة كاملة لقارئ الشاشة ومربع التلميح، ومتاح النص المختصر المرئي في عرض الهاتف دون فتح قائمة لتحديد ماهيته.
3. على الهواتف حتى 600px نزيل فقط أيقونتَي الإشعارات والمظهر **من الصف الظاهر** لتقليل الزحام؛ خيار المظهر موجود أصلًا في قائمة المستخدم، وأُضيف إليها رابط الإشعارات وعدد غير المقروء.
4. تقليل الفجوات العرضية مع بقاء زر قائمة الأقسام والبحث والمستخدم والشركة والفترة، وتحديد عناصر تفاعلية بحدود تركيز لوحة المفاتيح.
5. اختبارات `tools/header_names.test.mjs` لحماية أسماء السياق الكاملة ومسار خيارات الهاتف.

## فصل واضح بين المنجز وغير المنجز
- هذه مرحلة UX موضعية فقط؛ ليست تصميمًا كاملًا لجميع صفحات المحاسبة أو المخزون أو المراجعة.
- لم نغيّر محركات الحسابات والقيود والصلاحيات/ملكية الملفات أو JWT أو API/أسرار النشر أو روابط Cloudflare.
- لم ننفذ اختبارات متصفح فعلية أو `npm test` على كمبيوتر المالك لأنه كان غير متصل أثناء التنفيذ؛ فحص بنية النص وJavaScript داخل بيئة التحرير ليس بديلاً عنها.
- لا تُعتَبر حماية tenant مكتملة بمجرد ظهور الشركة في الواجهة؛ التفويض الكامل على الخادم شرط إطلاق تجاري مستقل.

## اختبارات القبول قبل الدمج
1. `node --test tools/header_names.test.mjs`؛ و`node --check ui/layouts/topbar.js`.
2. `SQC_BUILD_MODE=preview python build.py` ثم فحص عدم وجود `dist/secure` وفحص `tools/preview_privacy.test.mjs` حسب CI الحالي.
3. Playwright / Edge: عرض 320 و360 و390 و600 و900 و1440 بكسل، RTL، عدم التمرير العرضي، وضوح الشركة والفترة، البحث والإشعارات والمظهر وقائمة المستخدم.
4. التبديل بين شركتين مستقلتين: تحديث اسم الشركة والفترة دون ظهور بيانات الشركة الأخرى؛ والتبديل إلى مراجعة مستقلة ثم أدوات مستقلة دون تسرب سياق المحاسبة.
5. اختبار `prefers-reduced-motion` وتكبير النص وتركيز لوحة المفاتيح، ثم حالة الهاتف مع فترة طويلة الاسم.
6. اجتياز اختبارات المحاسبة/المخزون/العزل والأمان كاملة؛ CI ثم مراجعة Claude قائد التطوير قبل `main`.

## متابعة التحول الشامل (لم تنفّذ بعد)
- P0: اختبارات عقود ومسارات جميع الأزرار والشاشات وعزل الشركات على الخادم.
- P1: Design Tokens/components موحدة وتفاصيل جداول المحاسبة والحركة المعيارية؛ لوحة قيادة دورية ومخزن شامل (استلام، صرف، نقل، جرد، دفعات/صلاحية، تكلفة، أثر قيود).
- P1: تفكيك حالات الشاشات القديمة بتدريج محسوب مع حفظ Registry والروابط والإعدادات.
- P2: مساعد AI سياقي مع سند وموافقة بشرية، وتقارير ونسخ PDF/Excel وتخصصات قطاعية.
- P2: مقارنة مرجعية مرخّصة مع Stripe/Linear/Ramp/Mobbin متى يتوفر اشتراك، لا استنساخ تصاميم محمية.
